# Agent Note: Collapse the source traits

Status: proposed

## Problem

The `sources` module's core smell: `stateless.rs` is a 130-line file whose entire job is to
**pretend a stateless source is a stateful one with empty state**. The adapter
(`SourceWrapper` + `PartitionWrapper`) confesses there is really only *one* source engine,
with "stateless" bolted on top of it rather than designed beside it. The layering is
`StatelessSource` → `SourceWrapper` → `StatefulSource` → `into_stream` — a public shell
around an adapter that is immediately discarded and re-wrapped. See the
[module review](../../../docs/reviews/sources-module-review.md) for the full audit; the
concrete issues:

1. **Two parallel trait hierarchies, two conventions** — `StatelessSourceImpl<V, T>` uses
   generic parameters where `StatefulSourceImpl` uses associated types; the adapter
   translates back (`type Value = V`). The `Kvt` trait exists to kill exactly this verbosity.
2. **`PhantomData` everywhere is a symptom** — both wrappers carry `PhantomData<(V, T)>`
   only because `V, T` live in the stateless trait's generics instead of its associated types.
3. **Inconsistent parameter order** — `SourceWrapper<V, T, S>` vs `PartitionWrapper<S, V, T>`.
4. **Self-consuming `build_part` + `unreachable!()`** — `SingleIteratorSource::build_part`
   does `self.0.take()` and panics on a second call; the "each part built exactly once via
   `&mut self`" contract is implicit and fragile (the InputFormat-era model Flink replaced).
5. **Part discovery rides the data plane** — `PartLister` emits discovered parts as
   `DataMessage(part, NoData, Timestamp::MIN)`: a control message smuggled through the data
   channel with a meaningless value and timestamp.
6. **`PartLister` re-sends every part on every `apply()`** — re-derived each schedule,
   deduped downstream by `contains_key`.
7. **Two operator-authoring models in one file** — `PartLister` implements raw `Logic` with a
   hand-dispatched eight-arm `match`; `StatefulSourcePartitionOp` implements `SafeLogic`.
8. **Lifecycle asymmetry + dead code** — `suspend` exists only on the stateless side; both
   traits carry commented-out `is_finished`; `struct PartitionsFinished;` is dead.
9. **`list_parts`/`build_part` sync on stateless, async on stateful** — an arbitrary
   capability gap (a stateless source can't do async discovery) papered over by wrapping sync
   bodies in `async`.
10. **Bespoke `CommUtility` completion protocol** — part-finished flows over a shared
    `COMM_CHANNEL_ID = u64::MAX`, hardcoded to worker 0, defended against misrouted delivery
    ("a stray delivery on another worker must not panic — just ignore it").
11. **Naming** — "part" is overloaded five ways (`Part`, `Partition`, `SourcePartition`,
    `PartitionState`, `PartLister`).
12. **A "stateless" source with hidden state** — `SingleIteratorSource`'s index timestamps
    are positional state, silently lost on restart.

## Proposal

Adopt the [redesign](../../../docs/reviews/sources-module-redesign.md):

1. **One `SourceImpl` trait** — `PartitionKey`/`Value`/`Timestamp`/`PartitionState`/
   `Partition` associated types; `async fn discover(&mut self) -> Vec<PartitionKey>`;
   `async fn open(&mut self, key, state: Option<PartitionState>) -> Partition`. Stateless is
   the special case `PartitionState = ()`. One `SourcePartition` trait — `poll`/`snapshot`/
   `collect`; the framework owns its lifecycle.
2. **Delete the `stateless.rs` adapter** — `SourceWrapper`, `PartitionWrapper`, both
   `PhantomData`s, the `StatelessSource` shell, and the round-trip through
   `StatefulSource::new`. The only stateless ceremony left is three no-op
   `snapshot`/`collect` lines, optionally generated by a `#[derive(StatelessSource)]` in
   `malstrom-macros` (mirroring `TTLState`).
3. **Framework-owned discovery and completion** — discovery runs on worker 0 at
   build/rescale and emits a first-class `Message::SourcePartitions(...)` control message
   instead of fake data; completion falls out of the existing epoch/barrier alignment (reader
   exhaustion → `distribute`'s frontier merge → `Epoch(MAX)`, reusing `merge_frontiers` in
   `keyed/distributed/remote_receiver.rs`), removing `PartitionFinished`, the shared
   `COMM_CHANNEL_ID`, and the hardcoded worker 0. Rescale keeps the keyed
   `Acquire`/`Collect`/`Interrogate` protocol.
4. **One operator model** — both the discovery operator and the reader operator implement
   `SafeLogic`; the `PartLister`'s manual dispatch disappears.
5. **Convenience constructors** — `Source::from_poll_fn` / `from_stream` / `from_iterator`;
   `SingleIteratorSource` becomes `Source::from_iterator`, **untimed by default** (the index
   timestamps become an explicit `enumerate()` variant).
6. **Naming** — `Part` → `PartitionKey`, `PartitionState` → `State`, `SourcePartition` →
   `Partition`; drop `PartLister`/`PartitionsFinished`.

Migration is incremental (each step compiles, doctests/examples keep passing): rename+merge
the traits inside `stateful.rs` first → delete `stateless.rs` → replace discovery-as-data →
replace `PartitionFinished` with frontier-merge → add the `from_*` constructors and migrate
examples → delete `keyed_old/`/`stateful_old.rs` (see
[remove-dead-reference-files](../../simplification/2026-08-22-remove-dead-reference-files.md)).

## Alternatives considered

- **Fix in place (patch the adapter, keep two hierarchies)** — the adapter *is* the smell;
  two parallel conventions for the same concept will diverge again. Rejected.
- **`Default`-seeded state** (`PartitionState: Default` with a default `snapshot() { () }`)
  — a default `snapshot() { () }` does not type-check once a source overrides
  `PartitionState = MyState`; the explicit `Option<PartitionState>` in `open` is chosen
  (documented in the redesign's Rust-mechanics note).
- **Per-source comm channel id** (previously proposed) — the redesign removes the
  `PartitionFinished` protocol entirely, so the protocol-fix proposal is superseded; see the
  [rejected note](../../rejected/bug-fix/2026-08-22-per-source-comm-channels.md).
- **Keeping the raw-`Logic` part-lister** — `SafeLogic` exists precisely so operators don't
  get the internal messaging invariants wrong; the hand-rolled eight-arm `match` is error-prone.

## Acceptance criteria

- The six migration steps land; `sources/stateless.rs` is deleted.
- `SingleIteratorSource` is replaced by `Source::from_iterator` (untimed by default); the
  `from_poll_fn`/`from_stream` constructors exist and are exercised by examples.
- No `PartitionFinished`, `COMM_CHANNEL_ID`, or hardcoded-worker-0 completion remains in the
  source path.
- Full test suite (50 unit + 11 doc) and the multi-worker examples stay green through every
  migration step.

## Risks

- **Discovery I/O in the framework's build path** — `discover` may block (list a bucket,
  query a broker); the job-start protocol on worker 0 must tolerate a slow discovery.
- **Frontier-merge completion is load-bearing** — the `merge_frontiers` `None`-skip behavior
  (remotes without a source partition don't block) must not regress epoch alignment or
  exactly-once guarantees.
- **Source-author API churn** — trait rename plus new associated types; mitigated by the
  `from_*` constructors and the `StatelessSource` derive.
